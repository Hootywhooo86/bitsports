# bitsports Live NHL Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Real NHL scores, a live game screen and on-phone game alerts (pre-game, every goal with full info, replay link, period stats, AI period recap from bitcall, final) for bitsports on Android and web, signed with the family key.

**Architecture:** Android polls `api-web.nhle.com` directly; a foreground service watches followed games every 15s, a pure `AlertPlanner` decides what to alert, and a Messenger-bound service in bitcall generates recaps on-device. The web page reads the same feed through a Supabase edge-function proxy (the NHL API sends no CORS headers). All parsing and alert decisions are pure Kotlin, unit-tested against saved real responses.

**Tech Stack:** Kotlin 1.9.24 + Jetpack Compose (BOM 2024.06.00), AGP 8.5.2, compileSdk/targetSdk 34, minSdk 26, org.json, JUnit 4; bitcall: Kotlin 2 + Compose, minSdk 30, llama.cpp via JNI; web: inline `index.html` (no build step); Supabase Deno edge functions.

**Spec:** `docs/superpowers/specs/2026-10-21-live-nhl-design.md`

## Global Constraints

- Hockey (NHL) only. No other leagues, no iOS, no server watching games, no Firebase, no accounts, no betting content.
- Data source: `https://api-web.nhle.com/v1/` (`score/now` → 307 → `score/YYYY-MM-DD`; `gamecenter/{id}/play-by-play`). Never poll faster than every 15s (`Cache-Control: max-age=17`).
- A stale score is never presented as live: show "updated Ns ago" once the last successful fetch is older than 45s.
- No alert is ever sent twice for the same event, across restarts and feed revisions.
- AI recaps use only facts from the supplied period data; if bitcall is unavailable, skip the recap; never fake one. Recaps are Android-only.
- 128bit family look (black, monochrome chrome, colour only on data, Silkscreen + Inter); every new visible or audible thing has a Customize switch; polish via `/design-taste-frontend`.
- Family signing key = Bitcall release key; bitsports CI reads repo secrets `FAMILY_KEYSTORE_BASE64`, `FAMILY_KEYSTORE_PASSWORD`, `FAMILY_KEY_ALIAS`, `FAMILY_KEY_PASSWORD` and fails loudly if missing.
- bitcall rules: AI off by default; no AI work during an active call; the main model is released during calls.
- Work on branch `family-redesign` (bitsports) and `claude/zen-curie-7sxzl9` (bitcall). Never commit credentials.

## Review Focus

- **The feed revises or removes a goal** (scorer corrected, goal overturned on review): no second goal alert; the live screen shows the corrected or removed goal. → Task 3 test `revisedGoalDoesNotRealert`, `removedGoalIsDroppedSilently`.
- **Network errors or NHL 5xx mid-game:** the watcher keeps going with back-off, the mini scoreboard says "updated Ns ago", nothing crashes, alerts resume and catch up without duplicates. → Task 3 test `staleLabelAfter45s`, Task 6 step "error back-off".
- **Postponed or delayed games** (`gameScheduleState` ≠ `OK`, or still `FUT` 90 minutes after start): no pre-game alert for a postponed game, and the watcher stops itself. → Task 3 test `postponedGameGetsNoPregame`, `watcherGivesUpAfter90MinWithoutPuckDrop`.
- **Overtime and shootout:** OT period-end alerts say "OT"; shootout attempts don't fire goal alerts; the final says "won in a shootout". → Task 2 test `shootoutGoalsAreNotGoals`, Task 3 test `otPeriodLabel`.
- **A followed team typed loosely** ("oilers", "EDM", "Edmonton", "Utah"): it matches; nonsense doesn't, and the picker says it won't get live alerts. → Task 2 test `matchesLooseTeamText`.
